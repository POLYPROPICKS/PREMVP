1. Atomicity of the official Supabase API is unverified.
   - Location: the whole payload (L1-723), which has no transaction control.
   - Reason: the payload has no begin or commit of its own, so its all-or-nothing behavior rests on the API sending it as one simple-protocol Query. If the API splits statements, runs them in autocommit, or retries, a failure leaves partial Box B state.
     - With triggers blocking row deletion, cleanup would need an owner-level drop.
     - The replay guard would also block a clean retry.

   - Reason: the guard only tests that two Box B tables are absent. Run against the wrong project, the payload would create Box B there. This is a declared residual. The apply step must record project-ref binding as evidence (`nppznoujvnyjargjkmnv`).
